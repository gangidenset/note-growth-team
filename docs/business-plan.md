- 版: v0.1（フェーズ1）
- 作成日: 2026-10-23
- 注意: 本書の数値はすべて**計画値・仮定**であり、市場の実測値や実績ではない。実測で検証できたものから順に更新する。

## 1. 目標

| 項目 | 値 |
|---|---|
| 最終目標 | note での月間売上 **50,000円**（税込・手数料控除前の売上ベース） |
| 期間目安 | 立ち上げから6か月以内（仮。初月は売上ゼロも想定） |
| 判断基準 | 毎月の自社実績（noteダッシュボードの値）で評価する |

※「売上」と「手取り」を区別して管理する。手取りは手数料控除後。

## 2. 収益の仕組み（note）

- 収益源の候補: 有料記事（単品）、有料マガジン、メンバーシップ、サポート（チップ）
- MVPでは**単品の有料記事**から始め、反応を見てマガジン・メンバーシップを検討する。

### 手数料の仮定（要確認）
note の手数料は決済方法やプランで異なり、改定されることがある。以下は計画用の**仮置き**であり、フェーズ2開始時に note 公式ヘルプで確認し、確認日をここに記録する。

| 項目 | 仮定値 | 確認日 | 出典 |
|---|---|---|---|
| 手数料合計（決済手数料＋プラットフォーム利用料） | 売上の約15〜20% | 未確認 | note公式ヘルプ（要確認） |
| 振込手数料 | 1回数百円程度 | 未確認 | 同上 |

以下の計算では保守的に「手取り率 80%」を仮定する。

## 3. 売上シナリオ（計画値）

| 単価 | 必要販売数/月 | 手取り概算（80%仮定） |
|---|---|---|
| 300円 | 約167本 | 約40,000円 |
| 500円 | 100本 | 約40,000円 |
| 980円 | 約52本 | 約40,000円 |
| 1,980円 | 約26本 | 約40,000円 |
| 2,980円 | 約17本 | 約40,000円 |

### ファネル仮説（すべて未検証の仮定）
```
無料記事の閲覧 (PV) → 有料記事ページ閲覧 → 購入
```
- 仮に「無料記事PV→有料記事閲覧」10%、「有料記事閲覧→購入」2〜5% とすると、
  980円で52本売るには 有料記事閲覧 約1,000〜2,600、無料記事PV 約1万〜2.6万/月 が必要。
- これらの転換率は**一般論ベースの仮置き**であり、公開後の自社実績で置き換える。

## 4. 対象ジャンルと初期仮説

オーナーの得意分野: スマホ用アプリ開発、デモアプリ作成、将棋、スロット、テニス、ゲーム（Switch 2）。
以下の優先度は**仮説**であり、フェーズ3で market-researcher が出典付きデータで検証してから決める。

| ジャンル | 有料記事との相性（仮説） | 注意点 |
|---|---|---|
| スマホアプリ開発・デモアプリ作成 | 手順・ソースコード・テンプレートは有料部分にしやすい | 技術情報の正確さ、バージョン明記 |
| ゲーム（Switch 2） | 攻略・情報記事は需要が出やすいが、発売直後の時期に左右される | 権利者ガイドライン、ネタバレ配慮 |
| スロット | 有料の解析・攻略記事は一般に見かける | 収支保証表現の禁止、収支は本人実績のみ |
| 将棋 | 戦法解説・上達法 | 棋力の表記は事実のみ |
| テニス | 上達法・練習メニュー | 体験談はオーナー本人の記入のみ |

**追加の案（仮説）**: 「AI（Claude Code）でアプリやこのシステムを作った過程」自体が、アプリ開発ジャンルの記事ネタになりうる。この開発ログを残しておく。

最初はジャンルを1〜2個に絞って無料記事を出し、反応（自社実績）で絞り込む方針とする。

## 5. 戦略の骨子

1. **テーマ選定は「需要の証拠」と「自分が書ける根拠」の両方で決める**
   - 需要の証拠: 公開されている観測値（類似記事の存在数、価格帯、スキ数、検索結果、Q&Aサイトでの質問の多さ等）。他者の販売数は推測で断定しない。
   - 書ける根拠: オーナーの経験・実績・独自データ。
2. **無料記事で信頼を作り、有料記事で具体的手順・テンプレート・事例を提供する**
3. **小さく出して計測する**: 最初の1か月は価格帯を変えた有料記事を数本出し、自社実績で判断する。
4. **品質と誠実さを優先**: 誇大表現・根拠のない収益保証をしない（景品表示法・note規約対応、信頼の毀損防止）。

## 7. コスト見込みと予算

- 月額予算上限: **10,000円**（2026-10-23 オーナー決定。Claude Code・ツール等の合計）
- `.env` の `NGT_MONTHLY_BUDGET_JPY` に同じ値を設定する。

### Claude Code の契約形態: サブスクリプションを推奨
| 観点 | サブスクリプション（推奨） | API従量課金 |
|---|---|---|
| 費用の予測 | 月額固定で予算管理しやすい | 使った分だけ課金。使いすぎると上限を超えるおそれ |
| 秘密情報 | APIキー不要（ログインのみ） | APIキーの管理が必要 |
| 初心者の扱いやすさ | 高い | 使用量の監視が必要 |
| 向いている用途 | 対話しながらの開発・執筆（本プロジェクト） | 無人の自動実行・大量バッチ処理 |

- 予算10,000円以内に収まるプランを選ぶ。プラン名・料金・為替は変わるため、**契約前に公式の料金ページで確認**する（ここには確認日と選んだプラン名だけを記録する）。
- 契約・購入は課金操作のため、オーナー自身が行う。
- 将来、無人の定期実行が必要になったら API 従量課金との併用を再検討する（その場合も予算上限内で、事前承認を得る）。

| 項目 | 内容 | 金額 |
|---|---|---|
| Claude Code | サブスクリプション（予算内のプラン） | 契約時に確認・記録 |
| その他ツール | 現時点で有料ツールは使わない | 0円 |

有料ツール・API利用の追加は、課金操作として**事前承認制**とする。

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| 需要の読み違い | 小さく出して自社実績で検証、テーマを入れ替える |
| 捏造・誇大表現による信頼失墜/規約違反 | 出典必須スキーマ、品質チェック、承認ゲート |
| 他者コンテンツの模倣・著作権侵害 | 引用ルール遵守、競合記事は構成の観察にとどめ本文を複製しない |
| AI生成文章の均質化 | オーナーの実体験・独自データを必ず盛り込む工程を設ける |
| 手数料・規約の変更 | 確認日を記録し、四半期ごとに再確認 |
| APIコスト超過 | 予算上限を `.env` に設定し、超過前に確認 |
