# 要件定義書 — note収益化AI社員システム

- 版: v0.1（フェーズ1）
- 作成日: 2026-10-23
- ステータス: ドラフト（オーナー確認待ち）

## 1. 目的

note（note.com）で記事を販売し、**月間売上5万円**を達成するための業務を、Claude Code の Subagents と Skills で構成した「AI社員チーム」で支援する。
AIは調査・企画・執筆・品質確認までを担当し、**公開の最終判断と公開操作は必ず人間が行う**。

## 2. 用語

| 用語 | 意味 |
|---|---|
| オーナー | このシステムの利用者（人間）。承認・公開・課金の最終責任者 |
| AI社員 | `.claude/agents/` に定義された Subagent |
| Skill | `.claude/skills/` に定義された、AI社員が共通で使う手順書 |
| 記事パッケージ | 1テーマ分の無料記事・有料記事・メタ情報のまとまり |
| 承認 | オーナーが記事パッケージの特定版（内容ハッシュ）を公開してよいと記録すること |
| 実測 (observed) | 出典ページ上で直接観測できた値（例: 価格、スキ数、公開日） |
| 推定 (estimated) | 実測値から計算・推論した値。根拠と計算式の記録が必須 |
| 自社実績 (self_reported) | オーナー自身のnoteダッシュボード等で確認した自アカウントの数値 |

## 3. スコープ

### 対象（In Scope）
1. 市場調査: テーマ候補の発見、競合記事の観測、需要仮説の記録
2. マーケティング: テーマ選定、価格設計、無料→有料の導線設計、タイトル案
3. 編集・執筆: 無料記事・有料記事の下書き作成、推敲
4. 品質・分析: 事実確認、捏造チェック、表現チェック、公開後の自社実績分析
5. ワークフロー: 記事の状態管理、承認ゲート、監査ログ、進捗記録

### 対象外（Out of Scope、少なくともMVPでは）
- noteへの**自動投稿**（公式公開APIがないため。人間が手動で投稿する）
- 他者アカウントの非公開データ（購入数・売上）の取得・推測値の断定的記載
- 広告出稿などの課金を伴う施策の自動実行
- ログインが必要なページのスクレイピング、利用規約・robots.txtに反する収集

## 4. 機能要件

### FR-1 市場調査
- FR-1.1 テーマ候補ごとに、観測した競合記事・検索結果・トレンド情報を記録できる。
- FR-1.2 すべての市場データに以下を**必須項目**として記録する（欠けたデータは保存不可）。
  - `source_url`（出典URL。書籍等はタイトル・著者・ページ）
  - `source_title`
  - `retrieved_at`（取得日時、ISO 8601、タイムゾーン付き。例 `2026-10-23T10:15:00+09:00`）
  - `method`（取得方法: `manual` / `web_search` / `web_fetch` / `official_api` / `owner_dashboard`）
  - `measurement`（区分: `observed` / `estimated` / `self_reported`）
  - `estimated` の場合は `estimation_basis`（根拠となる実測データIDと計算式・仮定）
  - `collected_by`（担当: AI社員名 または `owner`）
- FR-1.3 外部アカウントの購入数・売上は**公開されていない限り記録しない**。推定する場合も「推定」と明記し、断定表現（「◯部売れている」）を禁止する。

### FR-2 マーケティング
- FR-2.1 テーマ候補を、需要・競合・自分の強み・制作コストで評価し、選定理由を記録する。
- FR-2.2 価格、無料記事と有料記事の役割分担、導線（無料記事→有料記事/マガジン）を設計する。
- FR-2.3 売上目標との差分から、必要な販売本数・価格帯をシナリオ計算する（計算は計画値であり実績ではないことを明記）。

### FR-3 編集・執筆
- FR-3.1 1テーマにつき無料記事1本以上・有料記事1本を作成できる。
- FR-3.2 記事内の事実主張は、市場データまたは信頼できる出典に紐づける。
- FR-3.3 有料記事には「無料部分」と「有料部分」の境界を明示する。

### FR-4 品質・分析
- FR-4.1 公開前チェックリスト（事実・出典・捏造・誇大表現・著作権・規約）を実行し、結果を記録する。
- FR-4.2 チェック未完了、または重大指摘が残る記事は承認待ちに進めない。
- FR-4.3 公開後、オーナーが入力した自社実績（PV・スキ・売上）を集計し、週次・月次レポートを作る。

### FR-5 承認・状態管理（最重要）
- FR-5.1 記事パッケージは状態機械で管理する（詳細は architecture.md）。
- FR-5.2 `approved` への遷移は**オーナーのみ**が実行できる。AI社員（Claude Code）からは実行できないよう、CLI・設定・フックの多層で防ぐ。
- FR-5.3 承認は記事の**内容ハッシュ**に紐づける。承認後に本文が1文字でも変わったら承認は無効となり、再承認が必要。
- FR-5.4 `published` への遷移は、有効な承認と公開URLの記録を必須とする。
- FR-5.5 すべての状態遷移を追記専用の監査ログ（誰が・いつ・何を・なぜ）に残す。

### FR-6 不可逆操作の承認制
以下は、事前にオーナーの明示的な承認がない限り実行しない。
- 課金が発生する操作（有料API、広告、有料ツール契約）
- 外部送信（メール、SNS投稿、外部フォーム送信、Webhookなど）
- 公開（note投稿、記事の公開範囲変更）
- 削除（ファイル・データ・Git履歴の削除、`git push --force`）

### FR-7 中断・再開
- FR-7.1 `docs/progress.md` に現在のフェーズ、完了事項、残課題、次の一手を記録する。
- FR-7.2 各記事パッケージは状態をファイルに保持し、セッションが途切れても状態から再開できる。
- FR-7.3 Claude Code は作業開始時に `docs/progress.md` を読み、終了時に更新する（CLAUDE.md で規定）。

## 5. 非機能要件

| ID | 区分 | 要件 |
|---|---|---|
| NFR-1 | セキュリティ | APIキー等の秘密情報は環境変数（`.env`）で管理し、Gitに登録しない。`.env` は `.gitignore` 対象。 |
| NFR-2 | セキュリティ | Claude Code の設定で `.env` の読み取りを禁止する。秘密情報をログ・ドキュメントに出力しない。 |
| NFR-3 | 誠実性 | 捏造禁止。不明な値は「不明」と書く。推定は推定と明記する。 |
| NFR-4 | 追跡可能性 | 市場データ・承認・遷移はすべてファイルに残り、Gitで差分確認できる。 |
| NFR-5 | 保守性 | 初心者が読めるよう、ドキュメントは日本語、コマンドは `npm run ...` に集約する。 |
| NFR-6 | コンプライアンス | note利用規約、著作権法、景品表示法（誇大表現）、特定商取引法の表示に留意する。※法的判断は専門家確認が必要。 |
| NFR-7 | コスト | API利用料の上限をオーナーが決め、`.env` の予算設定値を超える処理は実行前に確認する。 |

## 6. 前提・制約

- noteには一般公開の公式投稿APIがない（2026-10時点の当方認識。フェーズ2で公式情報を再確認する）。そのため公開は手動。
- 他者の記事の販売数は原則非公開。観測可能なのは価格・スキ数・公開日・著者のフォロワー数など公開表示されている値のみ。
- note の手数料体系は変更されうる。収益計算に使う手数料率は `docs/business-plan.md` に「仮定」として置き、公式ヘルプで確認した日付を記録する。

## 7. 受け入れ基準（システム全体のMVP）

1. 出典項目が欠けた市場データは保存時にエラーになる。
2. AI社員（Claude Code）からの承認操作がブロックされる。
3. 承認後に本文を編集すると、公開記録コマンドがエラーになる。
4. 1テーマについて、調査→企画→無料/有料記事→品質チェック→承認待ち、までを再開可能な形で通せる。
5. `.env` がGitに含まれていないことをテストで確認できる。

### ジャンル別の追加要件
- 匿名運用中は、記事・画像・スクリーンショットに本名・勤務先・居住地・顔・アカウントIDなど個人を特定できる情報を含めない（品質チェック F10 で確認）。

- **ゲーム（Switch 2）・将棋・テニス**: ゲーム画面・公式画像・棋譜等の利用は権利者のガイドラインに従う。発売日・仕様などの事実は公式情報を出典とする。
